# 轻书架每日签到设计

## 目标

为 `lightnovelshelf.js` 增加与禁漫天堂源相似的每日自动签到和手动签到能力，同时遵循轻书架真实的 SignalR 接口、UTC 日期口径和现有账号认证流程。

自动签到不是系统定时任务。开启后，用户每个 UTC 日首次实际使用轻书架源并完成一次普通 Hub 请求时，源在后台机会式签到；当天完全未使用轻书架则不会签到。

## 依据

### 禁漫天堂源的参考模式

`jm.js` 提供：

- “每日自动签到”开关，默认关闭；
- “手动签到”回调按钮；
- 进程内并发保护；
- 本地成功日期缓存；
- 在源产生 API 请求时机会式触发自动签到。

轻书架沿用这些用户交互和机会式触发思想，但不直接复制其请求头触发方式、本地时区日期和错误传播行为。

### 轻书架实际接口

轻书架网页端通过 SignalR 调用：

```text
SignIn({})
```

成功响应字段为：

- `Reward`：本次经验奖励；
- `CoinReward`：本次金币奖励；
- `Streak`：连续签到天数；
- `Exp`：签到后的累计经验；
- `Coin`：签到后的金币余额；
- `Level`：签到后的等级。

本功能只依赖展示所需的 `Reward`、`CoinReward` 和 `Streak`。轻书架签到日期以 UTC 为准，网页签到日历同样明确使用 UTC 年月和日期。

## 方案选择

采用“普通 Hub 调用成功后机会式触发”的方案：

1. 普通 `_hubCall` 成功取得结果后，后台检查是否需要自动签到。
2. 自动触发不被原漫画请求等待，因此不会增加列表、搜索、详情或章节返回时间。
3. 签到本身调用 `_hubCall("SignIn", {})`，并通过目标名称排除再次触发，避免递归。
4. 手动按钮复用同一个签到核心方法，但等待请求完成并向用户显示结果。

不采用只在 `init()` 中触发，因为登录发生在初始化之后或应用跨 UTC 日期持续运行时会漏签。不采用 `jm.js` 的请求头触发方式，因为轻书架 Long Polling 会频繁构造请求头，容易让签到逻辑与底层轮询耦合。

签到直接调用 `SignIn({})`，不预先调用 `GetSignInCalendar`。服务端负责最终的重复签到判定，本地状态负责避免源自身的重复请求。

## 状态模型

### 持久化状态

- `lastSignInUtcDate`：最后一次由当前源确认签到成功的 UTC 日期，格式固定为 `YYYY-MM-DD`。

该值只在 `SignIn` 成功且奖励响应可解析后写入。网络失败、服务端拒绝、重复签到错误或异常响应不得写入成功日期。

### 当前实例状态

- `_signInInProgress`：当前是否有签到请求正在执行，防止手动和自动签到并发。
- `_autoSignInAttemptDate`：当前源实例已经尝试自动签到的 UTC 日期。无论该次自动尝试成功还是失败，本实例当天都不再自动重试。

`_autoSignInAttemptDate` 不持久化。重新加载源后，若 `lastSignInUtcDate` 仍不是今天，则允许重新自动尝试；手动签到不受自动尝试日期限制。

### 账号隔离

签到开始时记录当前持久化 RefreshToken 的引用值。请求完成后再次读取并比较：

- 值相同：允许保存成功日期和显示成功消息；
- 值不同或已删除：说明账号在请求期间退出或重新登录，丢弃该次旧账号结果，不写入日期、不显示奖励。

退出登录时：

- 删除 `lastSignInUtcDate`；
- 清空 `_autoSignInAttemptDate`；
- 保留自动签到设置；
- 继续保留稳定的 `visitorId`；
- 按现有逻辑删除 RefreshToken 并清空短期 Token。

## 自动签到数据流

1. 普通 `_hubCall` 成功完成。
2. 若调用目标是 `SignIn`，直接跳过自动触发。
3. 自动触发器依次检查：
   - `dailySignInTask` 设置是否开启；
   - `this.isLogged` 是否为真；
   - `_signInInProgress` 是否为假；
   - `lastSignInUtcDate` 是否不是当前 UTC 日期；
   - `_autoSignInAttemptDate` 是否不是当前 UTC 日期。
4. 条件满足时，先将 `_autoSignInAttemptDate` 设置为今天，再以后台 Promise 调用签到核心。
5. 自动 Promise 不被原 `_hubCall` 等待，并显式捕获拒绝，避免未处理的 Promise 错误。
6. 成功后验证账号未变化、保存 UTC 日期，并提示奖励。
7. 未登录、今日已签、并发中或后台失败时保持静默，不影响原漫画请求。

只有普通 Hub 调用成功时才触发自动签到。若内容请求本身因网络或认证失败，则不额外启动签到请求。

## 手动签到数据流

设置页提供回调按钮：

```text
标题：手动签到
按钮：签到
```

点击后：

1. 若未登录，提示“请先登录轻书架账号”，不发送请求。
2. 若 `lastSignInUtcDate` 是今天，提示“今日已签到”，不发送请求。
3. 若正在签到，提示“签到正在进行中”，不发送第二个请求。
4. 否则调用 `SignIn({})` 并等待完成。
5. 成功后显示：

   ```text
   签到成功：连续 N 天，经验 +X，金币 +Y
   ```

6. 若服务端错误明确表示已经签到，显示固定消息“今日已签到”，但不将错误响应当作本源确认的成功，不写入成功日期。
7. 其他网络、服务端或响应格式错误显示“签到失败，请稍后重试”，不直接展示原始响应、Token、`x-id` 或完整服务端错误。

回调内部处理预期错误并正常结束，确保 Venera 按钮加载状态可以复位，不向设置页面留下未处理的 Promise 拒绝。

## 签到核心与响应校验

签到核心只负责一次受控请求：

1. 记录当前 RefreshToken 作为账号快照。
2. 设置 `_signInInProgress = true`。
3. 调用 `_hubCall("SignIn", {})`，复用现有短期 Token、RefreshToken 刷新和未授权重试逻辑。
4. 使用现有 `_value` 兼容 PascalCase/camelCase 字段。
5. 将 `Streak`、`Reward`、`CoinReward` 转换为数字，并要求全部为有限数字；奖励允许为 `0`。
6. 再次确认 RefreshToken 与账号快照相同。
7. 保存 UTC 日期并返回标准化结果。
8. 在 `finally` 中清除 `_signInInProgress`。

签到核心不得记录或返回认证令牌。累计经验、余额和等级不在 Venera 源内持久化，以服务端为唯一事实来源。

## 设置

在现有 `settings` 中增加：

- `dailySignInTask`
  - 标题：“每日自动签到”
  - 类型：`switch`
  - 默认值：`false`
- `dailySignIn`
  - 标题：“手动签到”
  - 类型：`callback`
  - 按钮文字：“签到”
  - 回调：执行手动签到

轻书架源已经直接使用中文设置标题，因此不新增独立翻译表。

## 提示与错误处理

### 自动模式

- 成功：显示连签天数、经验和金币奖励。
- 未登录、今日已签、并发中：静默返回。
- 失败：静默处理且不阻塞漫画请求。
- 当天当前实例不重复自动尝试，避免接口故障时每个分页请求都触发签到。

### 手动模式

- 所有前置状态均有明确中文提示。
- 成功提示奖励详情。
- 已签到错误转换为固定的安全提示。
- 其他错误使用通用提示，不回显 SignalR HTTP 正文或服务端原始异常。

## 兼容性和变更范围

- 不修改 `jm.js`。
- 不修改 `cache/Web` 或 `cache/Venera-Next`。
- 不新增真正的后台定时服务。
- 不展示签到日历、累计经验、金币余额或等级页面。
- 不改变账号登录、搜索、详情、章节分页和图片加载行为。
- `lightnovelshelf.js` 版本从 `0.2.7` 升级到 `0.2.8`。
- `index.json` 同步升级到 `0.2.8`，描述增加自动/手动签到能力。
- 文件顶部功能说明同步增加每日签到。

## 测试与验收

采用测试驱动方式，先验证旧实现缺少签到功能，再实现。测试覆盖：

1. `SignIn` 使用空对象参数调用。
2. `Streak`、`Reward`、`CoinReward` 被正确解析，奖励为 `0` 时仍有效。
3. 成功提示包含连签天数、经验和金币。
4. 日期使用 UTC `YYYY-MM-DD`，不依赖设备本地时区。
5. 成功后同一 UTC 日不再发起手动或自动请求。
6. 自动签到每天每个源实例最多尝试一次。
7. 自动失败不保存成功日期、不弹错误、不影响原 Hub 请求。
8. 自动失败后手动签到仍可立即重试。
9. 普通 Hub 调用成功后非阻塞触发；失败时不触发。
10. `SignIn` 目标不递归触发自动签到。
11. 未登录、并发中、重复签到和异常响应符合提示规则。
12. 请求期间退出或切换账号时不保存旧账号结果。
13. 退出登录清除签到状态但保留 `visitorId`。
14. 自动签到开关默认关闭，手动回调配置正确。
15. 账号登录、六种搜索模式和 225 页章节批量加载回归继续通过。
16. `lightnovelshelf.js` 与 `index.json` 版本和说明同步为 `0.2.8`。
